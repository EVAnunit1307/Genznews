Set up editor sign-in

A one-time setup for the site manager. Afterward, the editor just chooses Sign In with GitHub and starts writing.

You’ll need access to the website’s GitHub repository settings and its Vercel project settings. If you only write articles, ask the site owner to complete these steps for you.

1. Give the editor access

  1. The editor creates their own GitHub account, if needed.
  2. The repository owner opens Genznews → Settings → Collaborators, chooses Add people, and invites the editor’s username with permission to write.
  3. The editor accepts the invitation while signed into their own account.

The editor does not need Vercel access for everyday publishing. If they will also manage the website, arrange their own access to Vercel and ownership of the sign-in app.

2. Create the sign-in app

The person managing sign-in opens Register a new OAuth application in their GitHub account and enters:

Application name
genzthinks Editor
Homepage URL
https://genznews.vercel.app
Application description
Sign in to publish on genzthinks
Authorization callback URL
https://genznews.vercel.app/api/callback

Leave device flow off. Click Register application, then Generate a new client secret. Keep this page open.

3. Connect it in Vercel

  1. Open the Vercel dashboard, select this website’s project, and go to Settings → Environment Variables.
  2. Add GITHUB_OAUTH_ID and paste the Client ID from GitHub as its value.
  3. Add GITHUB_OAUTH_SECRET and paste the client secret as its value.
  4. Select Production for both and save. The secret belongs only in Vercel; do not paste it into the editor or send it in a message.
  5. Make sure the latest login code has been deployed. In Deployments, open the latest production deployment’s menu, choose Redeploy, and wait until it says Ready.

4. Try signing in

  1. Open the editor in a private browser window to test a fresh login.
  2. Choose Sign In with GitHub, use the editor’s account, and approve the genzthinks Editor app. Repository access lets it save articles.
  3. Confirm the article list opens. Publish a small test article with Draft switched on, check that Vercel deploys successfully, then delete the test article. Draft files are still in the public repository, so use only public test text.

For everyday use, bookmark the editor in your normal browser. If you’re asked to sign in again later, use the same GitHub button. You never need to make or paste a personal access token.

Need a hand?

The site still says setup is needed
Check both variable names and values in Vercel’s Production environment, then redeploy.
GitHub says the callback URL is wrong
Use https://genznews.vercel.app/api/callback exactly in the OAuth app settings.
Nothing happens, or the attempt expires
Allow popups and cookies for the website. Close the sign-in window and start again from the editor.
Signed in, but cannot publish
Confirm the editor accepted the repository invitation and is using that GitHub account. If saving works but the site does not update, ask the site manager to check the latest Vercel deployment.
Repeated sign-in errors
Check the Client ID and secret belong to the same OAuth App, then redeploy after correcting them.
The site uses a different address
Ask the site maintainer to follow the domain-change instructions in ADMIN-SETUP.md in the repository. The app settings, editor configuration, and Vercel setting must agree. Use the production editor, not a preview link.
